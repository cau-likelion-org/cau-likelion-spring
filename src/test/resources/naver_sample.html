오늘은 개발자라면 익숙한 Git과 GitHub를 소개한다. 비슷한 이름 때문에 동일한 서비스로 오해하는 경우가 종종 있는데 이 둘은 엄연히 다른 역할을 수행한다.

​

최근 클로드 코드 같은 AI 도구를 활용해 비전공자도 프로그래밍에 뛰어들고 있다. 특히 수익형 웹사이트와 웹앱 개발이 큰 인기다. 아이디어만 있으면 HTML, CSS, JavaScript, Pyrthon, Node.js, MySQL 등을 몰라도 누구나 쉽게 구현이 가능하기 때문이다.

​

그런데 다른 건 몰라도 지금부터 소개할 깃과 깃허브만큼은 꼭 숙지해 놓길 권한다.

​

1. Git 분산 버전 관리 시스템

우리는 과제, 보고서, 제안서 등을 만들 때 수시로 Word(.docx) 파일에 'v1', 'v1.1', 'v1.1.2' 등을 붙인 복사본을 만든다. 그런데 나중에는 어떤 파일이 최신인지, 어떤 버전에서 어떤 내용이 추가되고 삭제됐는지 알 수 없는 혼란에 빠진다.

​

Git은 이러한 비효율을 해결하기 위해 태어났다. 핵심은 버전 관리다. 파일의 변경 사항을 시간순으로 기록하고 필요할 때 언제든 특정 과거 시점으로 되돌릴 수 있게 해준다.

​

1. git init : 새로운 Git 저장소를 만든다. 프로젝트 폴더 안에서 실행하면 .git 폴더가 생긴다. 2. git clone <URL> : GitHub나 다른 곳에 있는 저장소를 내 컴퓨터로 복사한다. 처음 시작할 때 가장 많이 쓴다. 3. git add <파일> 또는 git add .: 변경한 파일을 '스테이징' 영역에 올린다. . 을 쓰면 모든 파일을 한 번에 올린다. 4. git commit -m "메시지" : 스테이징된 변경을 실제 기록(커밋)으로 저장한다. 메시지는 꼭 의미 있게 적는다. 5. git status : 현재 상태를 확인한다. 어떤 파일이 변경됐는지, 스테이징됐는지 한눈에 본다. 6. git push : 로컬 커밋을 GitHub(원격 저장소)로 올린다. 7. git pull :원격 저장소의 최신 내용을 내 로컬로 가져온다. 다른 사람이 수정한 걸 받을 때 필수. 8. git branch : 브랜치 목록을 보여주거나 새 브랜치를 만든다. 9. git checkout <브랜치명> : 브랜치를 이동한다. -b 옵션을 붙이면 만들면서 이동한다. 10. git merge <브랜치명> :다른 브랜치의 변경을 현재 브랜치로 합친다.

깃은 후술할 깃허브와 다르게 인터넷 연결 없이도 로컬 환경에서 독립적으로 동작한다. 그리고 단순한 버전 관리뿐만 아니라 Git에 올라간 모든 파일을 추적하고 기록한다. 덕분에 누가 언제 어떤 파일의 특정 라인 코드를 변경했는지 손쉽게 확인할 수 있다.

​

내가 생각하는 Git의 가장 매력적인 특장점은 브랜치(Branch) 기능이다. 이름에서 예상할 수 있듯이 나무줄기에서 가지가 뻗어 나오듯 원래의 코드 흐름을 건드리지 않고 새로운 기능을 추가하거나 테스트할 수 있는 독립적인 작업 공간을 만들 수 있다. 여기서 작업을 진행한 뒤 문제가 없으면 원본 줄기에 합치면(Merge) 된다. 따라서 해당 특장점은 특히나 팀 단위의 프로젝트 진행 시 안전하고 효율적인 코드 유지 관리에 필수다.

​

2. GitHub 코드 관리 클라우드 플랫폼

깃이 개발자 컴퓨터 내부에서 기록을 관리하는 도구라면 깃허브는 온라인 기록소에 해당한다. 클라우드 서비스인 구글 드라이브, 드롭박스와 비슷하지만, 단순한 파일 저장을 넘어 개발에 특화된 협업 기능까지 제공한다.

​

GitHub은 Git으로 관리하는 프로젝트를 인터넷상에 손쉽게 공유할 수 있게 해준다. 이를 통해 다른 누군가 만든 코드를 내 저장소로 가져와(Fork) 활용하거나 버그를 수정해서 원본 프로젝트에 반영해달라고 요청(Pull Request)할 수 있다. 괜히 거의 모든 오픈소스 프로젝트가 깃허브를 사용하는 게 아니다. 그리고 GitHub는 자신의 실력을 증명하는 포트폴리오의 역할까지 수행한다.

YouTube ReVanced도 깃허브를 활용하고 있는 대표적인 오픈소스 프로젝트다.

정리하면 Git 분산 버전 관리 도구 자체이고 GitHub는 그 도구를 온라인으로 확장한 서비스다. Git 없이 GitHub를 쓸 순 없지만, 깃허브 없이 깃은 쓸 수 있다. 참고로 비슷한 클라우드 서비스로 GitLab, Bitbucket이 있다.

​

최근 클로드 코드 같은 AI 툴로 아이디어를 현실화하는 사람이 부쩍 늘었다. 처음부터 Git과 GitHub를 조합해 버전 관리를 해보길 권한다. "언제 어떤 명령어를 써야 할지 모르겠어." 싶을 텐데 그마저도 AI한테 요청하면 된다. 이렇게 말이다.
